# 售后仓库管理系统

面向机器人本体、载荷、备件与耗材的内部仓库管理系统。服务端和微信小程序客户端保持在独立目录，便于先部署服务器、再逐步迭代移动端。

## 当前交付

- Web 工作台：单件资产与耗材配件、申请审批、出入库、通知、报表、二维码与 Excel 导入。
- Django 服务端：权限、可追溯审批流、操作审计、钉钉群机器人通知、健康检查。
- 审计日志检索：系统管理员可按操作人、动作、业务对象、对象编号和日期范围查询，并查看变更前后详情；日志页面只读。
- 呆滞库存分析：按最后库存动作日期识别长期未动的在库资产和耗材配件，支持阈值、仓库、物品类型、关键词筛选和 CSV 导出。
- 数据一致性检查：系统管理员可检查仓库/库位关系、重复识别码、预占数量、借用余额、申请明细和采购到货异常，并导出问题清单；检查不会自动修改数据。
- 四维状态一致性检查：系统管理员可发现资产实物位置、可用性、质量和处置之间不受支持的组合，结果支持页面筛选、CSV 导出和定时钉钉告警；检查只报告，不自动修正。
- 一致性处理建议：每类问题提供中文处理建议和对象跳转链接，管理员按申请、出入库、维修、盘点或资料维护流程处理，不直接改写派生状态。
- 数据一致性自动巡检：Ubuntu 部署后每日 03:00 运行同一套只读检查；首次发现、问题变化和全部恢复时通过钉钉群机器人通知，相同问题不重复通知，发送失败不会丢失重试状态。
- P0 安全底座：Service Worker 不缓存认证页面；离线队列按账号隔离并停止同步旧版本无主记录；DRF API 默认要求登录；资产照片和生命周期附件进行真实文件校验与图片重新编码；登录失败按账号/IP 摘要限流；认证令牌接口按账号/IP 摘要限流并在超限时返回 429；成功登录自动清理账号失败记录。
- API 令牌：继续使用 `Authorization: Token xxx` 请求头，令牌默认 30 天过期，支持 `/api/auth/token/rotate/` 轮换和 `/api/auth/token/revoke/` 撤销；服务端只保存令牌哈希，历史 DRF 令牌在迁移时转换后清理明文存储。
- 安全状态维护：每日 03:45 由 `after-sales-warehouse-security-cleanup.timer` 清理超过保留期的限流状态和失效 API 令牌，默认保留 90 天；支持 `manage.py prune_security_states --dry-run` 预览。
- 安全审计：失败登录和被限流拦截的登录会写入独立只增不改安全事件表，仅保存账号/IP摘要和事件类型，不保存密码或令牌原文。
- 资产状态兼容拆分：在保留旧版综合状态的同时，维护实物位置、可用性、质量和处置四个维度；历史数据已回填，状态变更会自动双写；工作台、库存候选、安全库存、低库存、补货、组装和 API 校验已采用四维可用性口径，旧状态继续作为兼容入口。
- 报表状态与价值口径：资产状态分布按实物位置、可用性、质量和处置四维展示；库存成本价值统计仍在内部仓库的资产和耗材配件，维修中、损坏或已预占资产仍计入库存价值。
- 资产预占口径：申请提交到撤回、驳回、过期、执行的全过程同步“已预占/可申请/暂不可用”；一致性检查会发现综合状态、有效预占与四维字段之间的矛盾。
- 资产台账支持按综合状态、实物位置、可用性、质量状态和处置状态组合筛选；资产检索和台账统一使用四维可用性判断，已预占或质量异常资产不会误报为可申请。
- 微信小程序代码：保留已有原型，当前阶段暂停开发和验收，不作为本阶段交付端。
- Ubuntu 22.04 实体机部署：PostgreSQL、Gunicorn、Nginx、systemd 与每日备份。
- 盘点任务：冻结账面快照，支持扫码核对、退回重盘、差异调整和 Excel 导出。
- 单据日期与编号：申请单支持申请/归还日期筛选，实际执行后生成按日递增的出入库单号，并保留关联申请单。
- 受控管理方式转换：耗材配件可拆分为独立编号资产，在库资产可合并为耗材配件；原记录和操作审计均保留。
- 库存导入：提供标准 Excel 模板、冲突预检、增量导入和全量基准导入。全量模式不删除历史记录。
- 库存提醒：工作台卡片可直接进入缺口、仓库和库位明细，桌面使用表格，移动端使用紧凑列表。
- 补货建议：仓库管理中的“补货建议”按安全库存计算缺口，支持按物品/供应商筛选和 CSV 导出；它是只读建议，不会自动修改库存或生成采购单。
- 采购草稿：可从补货建议勾选项目生成采购申请草稿，核对数量、原因和仓库/库位快照；支持编辑、删除和审计，但不会修改库存或生成正式采购订单。
- 采购审批：采购草稿提交后进入采购审批队列，审批人可同意或驳回，结果通过站内通知跳转；审批通过后可继续生成采购订单和到货入库。
- 采购订单与到货：审批通过后可生成待下达采购订单，支持手动下达、部分到货、多次到货、取消和到货日期；到货时耗材配件增加库存，单件资产自动生成 `AST-000001` 类系统编号，并同时生成采购入库单、库存流水和审计记录。
- 到货资产资料补录：到货登记时资产类物品可逐件录入生产厂家 SN、ERP 资产编码等资料（与台账全局查重）；也可事后在订单详情下载预填系统编号的 Excel 模板批量补录，补录写审计和资产履历。
- 供应商价格与采购到货汇总：按供应商+物品汇总历次采购单价（最新/最低/最高），按供应商+期间并可按下单日期/到货日期汇总订单数与订购/到货金额，均支持筛选和 CSV 导出；不等同于财务付款对账。
- 批量申请与快速办理：一张单据可混合选择多个单件资产和耗材配件；资产固定为 1 件，耗材配件逐项填写数量，所有明细共用同一业务类型。
- 个人耗材借用余额：耗材“借用”执行后记录本人尚未归还量，普通员工只能归还本人实际借用且尚未归还的数量；“领用”视为消耗，不形成可归还余额。
- 库存预占：申请提交后预占对应资产或耗材数量，驳回和撤回自动释放，实际出库后转为已执行；快速出入库、调拨和管理方式转换不能绕过有效预占。
- 申请效率：支持申请草稿、常用表单模板、“我的借用”及统一搜索/扫码输入；扫码优先使用浏览器原生识别，不支持时自动回退本地 ZXing 组件，模板不保存具体物品。
- 归还提醒：每天检查三天内到期、当天到期和已逾期借用，发送可跳转原申请的站内通知及钉钉群汇总，同一天重复执行不会重复发送。
- 库存占用治理：申请提交后立即占用库存，待审批占用默认 72 小时有效，超时自动关闭整张申请并释放；审批通过后转为待出库占用，不会自动释放，仓库看板支持人工延长和关闭。
- 借用延期：普通员工从“我的借用”提交延期，审批人员在“库存占用与借用”看板处理；同一借用单的归还日期和耗材借用明细同步更新。
- 钉钉个人通知：支持绑定企业通讯录 `userid` 并通过企业内部应用发送个人工作通知；未配置、未绑定或发送失败时保留站内通知并回退群机器人。
- 资产生命周期与维修：按单件资产统一汇总出入库、盘点、维修、交接和附件；维修支持内部/外部/质保、RMA、物流、预计返厂和成本，完成后恢复维修前状态，报废继续走现有审批。
- 移动扫码：同一输入框兼容关键词、编码、扫码枪和手机摄像头；支持连续识别、手电筒、前后镜头切换，并在成功加入物品后播放提示音和振动。扫码浮层逐条保留本次成功、重复和失败结果，停止后自动回到已选清单。
- 信息降噪：未读通知及待办单据保留完整卡片；已读通知和已结束申请自动收为紧凑摘要行，仍可点击进入详情。
- PWA 离线工作：申请草稿和盘点扫描可自动同步；快速出入库断网时保存带 UUID 的本机记录，联网后只进入服务器复核队列，经仓库人员按实时库存校验后才执行。重复同步不会重复记账，冲突可重试或拒绝。
- 业务基础资料：客户、供应商、维修服务商、项目和工单集中维护，表单选择后自动回填历史文本字段，兼容现有报表、接口和 Excel。
- NUC 运维保障：systemd 定时健康检查与每日校验备份，故障/恢复钉钉通知、日志保留策略及独立测试库恢复演练。
- 一致性巡检状态文件：`/srv/after-sales-warehouse/consistency-check.state.json` 只保存告警指纹和状态，不保存业务数据。

## 单据查询与编号

申请列表、我的审批和出入库记录均支持关键词、类型、状态、仓库、项目、工单及日期范围筛选。日期筛选使用业务日期，例如将起止日期都设为当天即可查询当天单据。

新申请单号格式为 `REQ-YYYYMMDD-000001`，出入库单号格式为 `IO-YYYYMMDD-000001`。申请单号在申请创建时生成，出入库单号仅在实际执行出入库时生成；同一申请的多个物品明细共用一个出入库单号。历史随机尾码单号保持不变，仍可检索。

## Windows 本机验收

双击根目录的 `start_dev.bat`。脚本会检查依赖、执行迁移并启动：

- Web：`http://127.0.0.1:8000/`
- 健康检查：`http://127.0.0.1:8000/health/`
- Django 管理后台：`http://127.0.0.1:8000/admin/`

修改服务端代码后，请停止原启动窗口并重新运行 `start_dev.bat`，使 Django 加载最新代码。

如果 Windows 提示 `attempt to write a readonly database`，先停止本地服务，再运行根目录的 `repair_sqlite_readonly.bat`。脚本会完整备份原数据库、重建文件权限并执行迁移，不会清空业务数据。

## 库存管理方式与 Excel 导入

- `单件资产`：每件有独立系统编号和二维码，适合机器人本体、雷达和电脑等设备。
- `耗材配件`：按总数量管理，适合线材、接插件和通用备件。旧 Excel 中的“数量物料”仍能兼容识别。
- `增量导入`：新增不存在的数据并更新唯一匹配的数据，文件中没有的库存保持不变。
- `全量基准导入`：只影响 Excel 中出现的仓库；缺失的在库资产标记停用，缺失的耗材配件库存归零，并保留复核问题和审计记录。

导入前可从“仓库管理”页面顶部的“Excel 导入”下载模板，也可直接使用项目根目录的 `仓库导入模板.xlsx`。系统按仓库系统编号、公司 ERP 编码、生产厂家 SN、生产厂家条码、本系统二维码或耗材配件编码匹配，冲突记录不会自动猜测或写入。

## 申请与快速出入库

- 普通员工申请开放“借用、领用、归还”。候选卡片不显示精确库存和详细仓位，仓库人员可查看这些定位信息。
- 单件资产按逐件编号选择，每条明细固定为 1 件，不显示无意义的数量框。
- 精确扫码即使遇到状态不匹配的资产也会加入清单并标红，展示当前状态和不能办理的原因；无效项可保存草稿，但不能正式提交或执行快速出入库，切换业务类型后会即时重新判断。
- 耗材配件可以与资产放在同一张单据中，每项独立填写数量；提交和实际执行时服务端都会重新检查状态、库存和归还余额。
- 借用显示并要求预计归还日期；领用不显示归还日期；归还隐藏接收人信息，只允许选择本人持有的资产或本人尚未归还的耗材。
- 快速出入库支持全部业务类型。调拨和归还要求目标仓库、目标库位；维修、报损、退供应商和报废只允许选择单件资产。
- 仓库管理的高频工具已集中到页面顶部，资产与耗材台账使用固定高度内部滚动区。
- 候选区只保留一个输入框：可按中文名、拼音、别名和备注搜索，也可输入系统编号、SN、二维码内容或接收扫码枪输入。精确编码按回车会直接加入，普通关键词按回车会显示候选列表；点击“扫码”后摄像头保持开启并逐件加入，重复资产自动去重。点击“停止扫码”不提交单据，只关闭摄像头并保留本次已选物品；填写申请信息后仍需点击“提交并预占”或“确认执行”。
- 申请提交时才占用库存，草稿不会占用；已预约但尚未实际出库的资产仍保持“在库”实物状态，但不再计入可申请量和安全库存可用量。
- 离线直接办理不会在手机上先扣库存。记录联网后显示在“离线操作”，复核人可看到物品当前状态和仓位；执行成功后才生成 `IO` 单据，状态不一致或库存不足则保留为冲突。

## 业务基础资料

系统管理员从“仓库管理 -> 业务基础资料”维护客户、供应商、维修服务商、项目和工单。项目可关联客户，工单可关联项目与客户；停用资料不会出现在新表单中，但历史单据仍可查看。未建档的临时对象仍允许手工填写文本，避免阻塞紧急业务。

## NUC 健康、备份与恢复演练

```bash
sudo /usr/local/sbin/after-sales-warehouse-health
sudo systemctl start after-sales-warehouse-backup.service
sudo /usr/local/sbin/after-sales-warehouse-restore-drill
sudo /usr/local/sbin/after-sales-warehouse-status
```

健康检查默认每 5 分钟运行；每日 02:15 备份数据库和附件。恢复演练只使用 `warehouse_restore_drill` 测试库，脚本明确拒绝生产库名称。钉钉告警复用 `/etc/after-sales-warehouse/quick-tunnel-dingtalk.env`，不在代码中保存 Webhook 或加签密钥。

## 机器人资产生命周期

- 从资产编辑页进入“生命周期与维修”，在一个页面查看完整时间线、维修台账、交接确认和附件归档。
- 维修申请审批并实际执行后自动建立维修台账；仓库录入人员也可手工补建维修单。进行中的维修单不允许重复建立。
- 维修完成或取消后恢复维修前的在库、借出或领用状态；已售出、已退供应商、已报废等最终状态不能建立维修单。
- 交接记录只确认实物、外观、配件和责任人，不绕过审批直接修改库存状态或持有人。
- 报废入口只创建现有申请与审批单，审批完成并由仓库执行后才更新资产状态。
- 维修报告、发票、物流凭证、设备日志等附件按资产归档，下载时重新校验登录和仓库角色，操作全程写入审计。

## 移动 Web/PWA 本机验收

移动端不需要单独启动服务。启动 `start_dev.bat` 后：

- Win11 浏览器访问 `http://127.0.0.1:8000/`，将浏览器视口切换为手机尺寸，检查底部导航、常用操作、申请和审批页面。
- 手机与电脑连接同一 Wi-Fi 时，访问 `http://电脑局域网IP:8000/`。电脑防火墙需要允许 Python/Django 开发服务的 `8000` 端口。
- 手机通过普通 HTTP 局域网地址可以测试业务页面，但浏览器通常不会允许安装 PWA，也不能稳定调用摄像头；PWA 安装和移动扫码应使用 HTTPS，例如后续的 Cloudflare Quick Tunnel 测试地址。
- 手机上添加到桌面后，打开的是同一套 Web 页面；数据仍由 Django 服务端保存。

## 小程序验收

使用微信开发者工具导入 `miniprogram/`。本机调试地址在 `miniprogram/miniprogram/utils/config.js` 中配置为 `http://127.0.0.1:8000`。

真机调试时，改为服务器在公司 Wi-Fi 上可访问的地址；正式发布前，使用 NUC 的 HTTPS 内网域名并在微信公众平台配置合法请求域名。详细步骤见 [小程序说明](miniprogram/README.md)。

## Ubuntu 部署

部署前先运行：

```bash
sudo bash deploy/ubuntu22/preflight.sh
```

Windows 本机生成纯净部署包：

```powershell
powershell -ExecutionPolicy Bypass -File .\deploy\ubuntu22\build-package.ps1
```

通过预检后，按 `Ubuntu22.04本机部署手册.md` 执行安装。不要把开发服务器端口直接暴露到公网。

部署后常用运维命令：

```bash
sudo /usr/local/sbin/after-sales-warehouse-status
sudo /usr/local/sbin/after-sales-warehouse-security-check
sudo /usr/local/sbin/after-sales-warehouse-rollback --list
```

零成本移动 Web 测试可以在 NUC 上执行 `deploy/ubuntu22/enable-quick-tunnel.sh` 创建 Cloudflare 临时 HTTPS 入口。该入口地址可能随 Tunnel 重启变化，仅用于测试，不用于正式小程序或生产访问。
